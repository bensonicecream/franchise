# 벤슨 가맹문의 DB — 설치·운영 안내

가맹 문의자가 접수폼을 제출하면 Firestore에 저장되고, 관리자 화면에서 STEP 1 등급(A 우선 상담 / B 상담 / C 보류)이 자동으로 계산됩니다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 가맹 상담 사전 확인서(접수폼). 외부 공개 |
| `admin.html` | 관리자 화면. 로그인 + 관리자 등록 계정만 사용 |
| `config.js` | Firebase 설정값, 개인정보 동의 문구, 선택 항목, 지역 목록, 등급 기본값 |
| `mail-parser.js` | 메일 회신 붙여넣기·엑셀 표 붙여넣기 → 항목 자동 채우기 (관리자 화면에서 사용) |
| `benson-logo.png` | 접수폼 상단 벤슨 로고 (흰색 글자, 투명 배경) |
| `benson-badger.png` | 접수폼 상단 벌꿀오소리 캐릭터 (투명 배경) |
| `firestore.rules` | 보안 규칙. 외부는 제출만, 조회·수정·삭제는 관리자만 |

## 설치 순서

1. **Firebase 프로젝트 만들기**
   점검앱·케이크 예약과 분리된 새 프로젝트를 권장합니다(가맹 희망자 개인정보를 다른 데이터와 분리). 무료(Spark) 요금제로 운영합니다.

2. **Firestore Database 만들기**
   위치는 `asia-northeast3 (서울)`을 권장합니다. 위치는 만든 뒤 바꿀 수 없습니다. 프로덕션 모드로 시작합니다.

3. **보안 규칙 게시**
   Firestore > 규칙 탭에 `firestore.rules` 내용을 전부 붙여넣고 [게시]합니다.
   ※ 규칙을 게시하기 전에는 접수폼 링크를 외부에 보내지 마세요.

4. **관리자 로그인 계정 만들기**
   Authentication > 시작하기 > 로그인 방법 > `이메일/비밀번호` 사용 설정 → 사용자 탭 > [사용자 추가] (본인, 팀장님 등).

5. **관리자 등록**
   Firestore > 데이터 > [컬렉션 시작]
   - 컬렉션 ID: `admins`
   - 문서 ID: 4번 계정의 **사용자 UID** (Authentication 사용자 목록에 표시)
   - 필드: `name` (string) = 이름
   사람마다 문서 1개씩 만듭니다. UID를 찾기 어려우면 먼저 `admin.html`에 로그인해 보세요. 화면에 UID가 표시됩니다.

6. **웹 앱 등록 → config.js 입력**
   프로젝트 설정 > 일반 > 내 앱 > 웹(`</>`) 앱 추가 → 표시되는 `firebaseConfig` 값을 `config.js` ①에 붙여넣습니다.

7. **개인정보 동의 문구 확인**
   `config.js` ②의 수집 목적·항목·보유 기간을 회사 개인정보 처리방침 기준으로 확인·수정합니다. (기본값 '접수일로부터 1년'은 임시 문구입니다.)

8. **GitHub Pages 배포**
   새 저장소에 `index.html`, `admin.html`, `config.js`, `mail-parser.js`, `benson-logo.png`, `benson-badger.png` 6개 파일을 올리고 Settings > Pages > Branch `main` / `(root)` 저장.
   - 접수폼: `https://<계정>.github.io/<저장소>/`
   - 관리자: `https://<계정>.github.io/<저장소>/admin.html`

9. **승인된 도메인 추가**
   Authentication > 설정 > 승인된 도메인에 `<계정>.github.io`를 추가해 둡니다.

10. **등급 기준 입력**
    관리자 화면 > 등급 기준 > 1·2순위 상권 키워드를 입력하고 [기준 저장]. (2027 우선 출점 지도의 1·2순위 상권을 시·군·구 또는 상권명으로 입력)

## 배포 후 확인

- [ ] 접수폼에서 시험 제출 → 관리자 목록에 바로 표시
- [ ] 로그아웃 후 `admin.html` 접속 시 로그인 화면으로 이동
- [ ] `admins`에 등록되지 않은 계정은 로그인해도 차단
- [ ] 엑셀 다운로드 정상
- [ ] 시험 데이터 삭제

## 관리자 계정 관리 (관리자 화면 > 관리자 계정)

처음 한 번만 Firebase 콘솔에서 본인 계정을 만들고 `admins`에 등록하면(설치 4·5단계), 이후 계정은 관리자 화면에서 만듭니다.

| 권한 | 할 수 있는 일 |
|---|---|
| 마스터 | 문의 조회·검토·등록 + 관리자 계정 추가·권한 변경·접근 해제 + 등급 기준 변경 |
| 일반 관리자 | 문의 조회·검토·등록 (등급 기준은 보기만 가능) |

- **새 계정 만들기**: 이름·이메일·임시 비밀번호(8자 이상, [자동 생성] 가능)·권한을 넣으면 로그인 계정과 관리자 등록이 한 번에 됩니다. 완료 후 [안내 내용 복사]로 주소·이메일·임시 비밀번호를 전달하세요.
- **기존 계정 UID로 등록**: 이미 Firebase에 가입된 이메일이면 새로 만들 수 없습니다. 그 사람이 관리자 화면에 로그인하면 표시되는 UID로 등록합니다.
- **권한 변경·접근 해제**: 계정 목록에서 바로 바꿉니다. 접근 해제한 계정은 로그인해도 데이터를 볼 수 없고 '다시 허용'으로 되살릴 수 있습니다. 본인 계정은 다른 마스터만 바꿀 수 있어, 실수로 스스로 잠기는 일을 막습니다.
- **비밀번호**: 각자 오른쪽 위 [비밀번호 변경]에서 바꿉니다. 잊어버린 경우 마스터가 계정 목록에서 [비밀번호 재설정 메일]을 보냅니다. 메일 언어는 Firebase 콘솔 Authentication > 템플릿에서 한국어로 바꿀 수 있습니다.
- 콘솔에서 직접 만든 기존 관리자(권한 값 없음)는 마스터로 처리됩니다.
- 로그인 계정 자체를 완전히 삭제하려면 Firebase 콘솔 Authentication > 사용자에서 삭제합니다.

## 문의 직접 등록 (관리자 화면 > 문의 직접 등록)

전화·메일·매장 방문 등으로 받은 문의를 한 건씩 입력합니다.

1. [문의 직접 등록]을 누르고 성함, 연락처(또는 이메일), 접수일, 유입 경로를 입력합니다. 나머지 항목은 아는 만큼만 넣어도 등록되며, 비운 항목은 0점으로 계산됩니다(아래쪽에 '미입력' 표시).
2. 메일로 받은 경우 위쪽 칸에 회신 메일의 1~10번 답변을 붙여넣고 [내용 자동 채우기]를 누르면 항목이 채워집니다. 자동으로 채운 값과 안내 문구를 확인·수정합니다.
3. 아래쪽 예상 점수·등급을 확인하고 [등록]

- 직접 등록한 건은 목록 유입 칸에 '(수기)', 상세 화면에 '개인정보 동의 체크 없음 (직접 등록)'으로 표시되고, 붙여넣은 메일 원문은 [메일 원문 보기]에서 확인할 수 있습니다.
- 등록한 응답은 상세 화면 [응답 수정]으로 고칠 수 있습니다(접수폼으로 들어온 문의도 동일).

## 엑셀 일괄 등록 (관리자 화면 > 엑셀 일괄 등록)

엑셀로 관리하던 문의를 한 번에 옮깁니다.

1. 엑셀에서 **제목 행(접수일, 성명 …)부터 마지막 행까지** 선택해 복사(Ctrl+C) → [엑셀 일괄 등록] 칸에 붙여넣기(Ctrl+V) → [미리보기]. 엑셀 파일을 직접 선택해도 됩니다(첫 번째 시트).
2. 미리보기에서 행마다 읽은 결과와 확인 사항(지역·금액·경험 해석 등)을 보고, 등록할 행만 체크한 채 [n건 등록]을 누릅니다.

- 인식하는 열 이름(비슷한 이름도 인식): 접수일, 성명, 연령대, 희망지역, 희망 출점시기, 예상 투자비, 후보물건 보유, 후보물건 정보, 에프앤비 경험, 지원동기, 비고, 1차·2차 회신일, 회신 방법, 연락처, 이메일. 그 밖의 열은 메모에 '열 이름: 값'으로 들어갑니다.
- 접수일이 '8/28(금)'처럼 연도 없이 적혀 있으면 요일이 맞는 해로 넣습니다. 투자비가 '2~3억'처럼 범위면 낮은 값으로 넣습니다.
- 비고와 회신 기록은 메모에 들어가고, 회신 기록이 있으면 처리 상태를 '검토 완료'로 넣습니다. 희망지역 원문은 그대로 남아 상세 화면에 보이고, 상권 키워드 판정에도 쓰입니다.
- 이미 같은 연락처의 문의가 있거나, 접수일로부터 보관 기간이 지난 행은 체크가 해제된 채로 나옵니다.
- 엑셀에 없는 항목(운영 참여 계획 등)은 0점으로 계산되니, 필요하면 등록 후 [응답 수정]으로 채워 주세요.
- 실제 문의자 정보는 코드 파일에 넣지 마세요. GitHub Pages 저장소는 공개되어 있습니다.

## 단계별 평가와 접촉 이력

가맹 희망자는 **1차 기본평가 → 접촉(유선 상담) → 2차 심층 상담평가 → 출점 심의 → 가맹계약** 순서로 관리합니다. 문의를 누르면 상단에 진행 단계가 표시되고, 아래 세 탭으로 나뉩니다.

| 탭 | 내용 |
|---|---|
| 1차 평가·진행 | 접수 정보로 자동 계산한 1차 점수·등급(A/B/C), 응답 내용, 진행 단계·우호도·등급 조정·메모 |
| 접촉 이력 | 전화·문자·메일·대면 상담·방문 기록을 일시·내용·다음 할 일·예정일과 함께 남김. 기록자 자동 저장, 수정·삭제 가능 |
| 2차 심층평가 | 대면 상담 후 항목별 1~5점(정량), 리스크 체크와 종합 의견(정성), 최종 판정(심의 상정 / 보완 후 재상담 / 부적합) |

- **진행 단계**: 미확인 → 1차 검토 완료 → 유선 상담(STEP 2) → 대면 상담·2차 평가(STEP 3) → 출점 심의(STEP 4) → 가맹계약 진행(STEP 5), 그 밖에 보류 안내·DB 보관, 종료. 접촉 기록을 추가할 때 함께 바꿀 수 있고, 2차 평가에서 최종 판정을 고르면 알맞은 단계로 바꿀지 묻습니다.
- **다음 할 일**: 접촉 기록의 '다음 할 일·예정일'이 목록의 '다음 일정'에 D-day로 표시됩니다. 예정일 당일 이후 연결된 접촉을 기록하면 처리된 것으로 보고, '연결 안 됨(부재)' 기록은 기존 예정을 지우지 않습니다.
- **목록 요약**: '2차 평가 대기'(1차 대상 등급 중 2차 평가 전, 보류·종료 제외)와 '연락 예정(오늘까지)'(오늘이거나 지난 예정)을 눌러 바로 걸러 볼 수 있습니다. 1차 대상 등급인데 접촉 기록이 없으면 '미접촉'으로 표시됩니다.
- **2차 평가 기준**: [평가 기준] 탭 아래쪽에서 항목명·배점·상담 확인 포인트, 리스크 항목, 대상 등급, 점수 구간을 바꿀 수 있습니다(마스터). 항목별 (점수 ÷ 5 × 배점) 합계를 100점으로 환산하고, 리스크는 점수와 별개로 표시합니다. 기본 항목·배점·확인 포인트는 초안이니 내부 기준으로 다듬어 쓰세요.
- **기존 엑셀 회신 기록**: 이전에 엑셀 일괄 등록으로 메모에 들어간 'n차 회신' 기록은 [접촉 이력] 탭의 [접촉 이력으로 옮기기]로 옮길 수 있습니다. 새로 일괄 등록하면 회신 기록이 처음부터 접촉 이력으로 들어갑니다.
- **엑셀 다운로드**: '가맹문의' 시트에 2차 평가·접촉 요약 열이 추가되고, '접촉 이력'과 '2차 평가'(항목별 점수) 시트가 함께 만들어집니다.

## 운영 방법

- **링크**: 관리자 화면의 [메일용 접수폼 링크 복사]를 안내 메일에, [홈페이지용 링크 복사](`?src=homepage`)를 홈페이지 가맹문의 팝업 버튼에 넣으면 유입 경로가 구분됩니다.
- **등급 항목**: 투자 여력, 희망 지역, 외식업 경험, 운영 참여, 연령대(합계 100점)로 계산합니다. 점포 확보·오픈 시기는 수집만 하고 점수에는 넣지 않습니다.
- **자동 삭제**: 접수일로부터 1년(`config.js`의 `RETENTION_MONTHS`)이 지난 문의는 관리자가 관리자 화면을 열 때 자동 삭제됩니다. 삭제 30일 전부터 목록에 '삭제 D-n'이 표시되며, 상세 화면에 삭제 예정일이 나옵니다. 진행 단계와 관계없이 삭제되며, 접촉 이력·2차 평가도 함께 지워집니다.
- **등급**: 기준을 저장하면 전체 문의가 즉시 다시 분류됩니다. 진행 단계를 바꿔 저장한 문의는 그때의 등급·점수가 따로 남습니다. 상세 화면에서 등급을 수동 조정할 수 있고, 목록에 '조정'으로 표시됩니다.
- **우호도**: 상담·통화 후 담당자가 높음·보통·낮음으로 표시합니다. 목록의 우호도 칸에서 바로 바꾸거나 상세 화면 [1차 평가·진행]에서 바꿀 수 있고, 필터와 엑셀에도 나옵니다. 자동 점수·등급에는 반영되지 않습니다. 단계 이름은 `config.js`의 `AFFINITY`에서 바꿀 수 있습니다.
- **중복**: 같은 연락처로 2번 이상 접수되면 목록에 '중복' 표시가 붙습니다.
- **미리보기**: `admin.html?demo` 로 접속하면 예시 데이터로 화면을 확인할 수 있습니다(DB 미연결).

## 수정할 때 주의

- `firestore.rules`를 바꾼 경우 Firestore > 규칙 탭에 다시 붙여넣고 [게시]해야 적용됩니다. (메일 문의 등록 기능은 관리자의 직접 등록을 허용하는 규칙이 필요합니다.)

- `config.js`의 Firebase 값은 공개되어도 되는 식별값입니다. 데이터 보호는 보안 규칙이 담당합니다.
- 선택 항목의 값(`v`)을 바꾸거나 항목을 추가하면 `firestore.rules`의 허용 값·필드 목록도 함께 수정해야 제출이 됩니다. 문구(`t`)만 바꾸는 것은 괜찮습니다.
- 접수폼 색은 로고 하늘색(`--sky: #7CA5D7`)과, 흰 글자를 올리기 위한 진한 하늘색(`--brand: #3E6FB2`)을 씁니다. `index.html` 맨 위 `:root`에서 바꿀 수 있습니다.
- 로고·캐릭터 이미지는 같은 파일 이름으로 덮어 올리면 교체됩니다. 캐릭터는 포스터 캡처에서 잘라낸 것이라 해상도가 낮으니, 원본 파일이 있으면 투명 배경 PNG로 교체하세요.
